# 구독 서비스 고객 이탈·리텐션 분석 (KKBox)

> 🚧 **작업 중입니다.** "진행 현황"에서 완료된 항목만 결과로 인정해 주세요. 모든 수치는 **사용자 1% 샘플** 기준이며 전체 모집단의 값이 아닙니다.

음악 스트리밍 구독 서비스 KKBox의 가입·결제·청취 로그로 **고객이 언제, 어떤 특징을 가지고 이탈하는지** 분석하고, 리텐션 개선을 위한 CRM 액션과 A/B 테스트 설계안을 제안하는 포트폴리오입니다.

## 핵심 요약 (현재까지)

- **첫 갱신 이탈은 무료 체험 사용자에 집중됩니다.** 7일 플랜(대부분 0원, 체험 추정)은 판정 가능자의 약 26%지만 첫 갱신 이탈의 약 62%를 차지하고, 유료 전환율은 4.76%입니다.
- **유료로 시작한 사용자(paid)의 구독 유지율은 1개월차 84.00%에서 12개월차 70.68%까지 완만하게 낮아집니다.** 0원으로 시작한 사용자(free_start)는 1개월차 37.64%에서 4개월차 이후 25~26% 근처로 내려갑니다.
- 구독이 끊긴 뒤에도 한동안 청취가 남는 사용자가 많습니다. paid 구독 미유지자 중 청취 비율은 1개월차 65.38%, 12개월차 12.04%입니다.
- 30일 플랜에서 자동 갱신 사용자의 1차 갱신률(86.03%)이 수동 갱신(70.08%)보다 높지만, 관찰 데이터라 인과로 단정하지 않습니다.

## 분석 질문과 가설

1. 첫 결제와 갱신 단계에서 어디서 가장 많이 빠져나가는가? (퍼널)
2. 이탈하는 고객은 어떤 특징을 가지는가?
3. 첫 결제월 코호트별 유지율은 어떻게 다른가?
4. 세그먼트별 행동과 유지율, LTV(근사치)는 어떻게 다른가?

초기 가설(분석 후 수정 예정): H1. 가입 후 초기 30일 활동이 적을수록 이탈 확률이 높다. H2. 자동 갱신 사용자는 이탈률이 낮다. H3. 결제수단과 플랜 기간에 따라 유지율이 다르다. H2·H3는 퍼널에서 단순 비교로 예비 근거를 봤고, 통계 검정과 회귀에서 다시 확인합니다.

## 분석 기준

### 모집단
- 샘플 회원 중 **결제 이력이 있는 사용자**만 분석합니다. 결제 이력이 없으면 갱신·이탈을 정의할 수 없기 때문입니다. 99명은 취소 거래만 있어 구독 이력이 만들어지지 않아 제외했고, 쿼리로 확인했습니다.
- 가입 초기 행동 지표(청취 로그 기반)는 로그 수집 시작일(2015-01-01) 이후 가입자 9,104명에 한해 씁니다. 그 이전 가입자는 가입 후 30일 로그를 볼 수 없어 0이 실제 0이 아니기 때문입니다.
- **이탈 특징 분석**은 무료 체험(7일 플랜·0원)을 제외한 유료 시작자만 대상으로 합니다. 체험의 미전환과 유료의 갱신 중단은 성격이 달라 섞으면 회귀 계수 해석이 흐려집니다. 0원 시작 비체험 사용자(free_start, 745명)를 포함할지는 해당 분석 단계에서 정합니다.

### 이탈 정의와 검증
- **구독 만료 후 N일(기본 30) 안에 재결제가 없으면 이탈**입니다. 만료 전에 다음 결제가 있는 조기 갱신·장기 플랜 연장은 유지로 봅니다. 취소 거래는 갱신으로 인정하지 않는 가정을 두었습니다(취소 시점 구분 없음). 아직 N일이 지나지 않은 건은 만료 건 기준에서 제외하고, 사용자 기준에서는 활동 중으로 취급합니다.
- **민감도**: N=15/30/45일에서 만료 건 기준 이탈률은 9.06%/7.82%/7.06%, 사용자 최종 이탈률은 44.9%/43.8%/42.8%입니다. N을 바꿔도 결론이 크게 달라지지 않습니다.
- **공식 라벨(`train.csv`) 비교** (샘플 내 8,767명, 공식 이탈률 6.38%): 본 정의의 일치도 97.51%, 만료일 이후 결제만 갱신으로 보는 규칙(v1)은 99.43%입니다. 본 정의가 놓친 공식 이탈자 217명 중 185명은 만료일 이전의 조기 갱신·장기 플랜입니다. 공식 규칙은 v1에 가까운 것으로 **추정**한 것이며, v1으로도 설명되지 않는 약 50명(0.6%)의 원인은 모릅니다.
- **기본값은 본 정의**입니다. 조기 갱신도 서비스를 계속 쓰는 것이라 유지로 보는 편이 비즈니스 해석에 맞다고 판단했고, v1은 견고성 확인용으로 병행합니다.

### 코호트 유지율
퍼널 B 코호트 중 취소 제외 거래가 있는 9,097명을 첫 결제월로 묶고, 첫 결제를 기준으로 trial(첫 플랜 7일) / free_start(7일 아님, 첫 결제 0원) / paid(7일 아님, 첫 결제 > 0원)로 나눕니다. 유지는 "첫 결제일 + k개월 + `buffer_days`(기본 7일) 시점에 구독이 유효한가"이며, 체크포인트가 데이터 종료일을 넘는 칸은 제외합니다. 활동 유지(보조 지표)는 그 달 안에 청취 로그가 하루라도 있는지입니다. 자세한 정의는 `sql/04_cohort_retention.sql`의 머리말을 참고하세요.

- 30일 플랜의 자동 갱신(86.03%) vs 수동(70.08%) 차이는 관찰된 차이입니다.

### 코호트 유지율 (구독 유지 기준, `buffer_days = 7`)

코호트 규모는 trial 2,230 / free_start 745 / paid 6,122명(합계 9,097명)입니다. 괄호는 그 월차의 분모입니다.

| 첫 결제 후 | paid | free_start | trial |
|---|---|---|---|
| 1개월 | 84.00% (5,843) | 37.64% (736) | 3.72% (2,230) |
| 3개월 | 79.60% (5,347) | 27.08% (720) | 3.51% (2,195) |
| 6개월 | 77.22% (4,715) | 25.60% (711) | 4.65% (924) |
| 12개월 | 70.68% (3,356) | 25.28% (629) | 5.61% (481) |

- **paid** 12개월차는 코호트에 따라 55~84%입니다. 2015-01~06 코호트(코호트당 86~139명)는 55~65%로 낮고 2015-07(227명)은 84%인데, 원인은 확인하지 않았고 통계 검정도 하지 않았습니다.
- **trial**은 2015-06(452명), 2016-10(454명), 2016-11(814명) 코호트에 몰려 있어(프로모션 시기로 추정, 미확인) 합산 곡선에 구성 변화가 섞입니다. 12개월 고정 코호트 481명 중 452명이 2015-06이라 사실상 코호트 한 개의 모습이므로 일반화하지 않습니다.
- **buffer 민감도**: paid 1개월차는 buffer 0/3/7/14일에서 81.28/82.08/84.00/85.71%로 달라지지만, 3·6개월차는 0~7일 차이가 1%p 안쪽입니다.
- **퍼널 갱신률과 다른 지표**입니다. 코호트는 "그 시점에 구독이 유효한가", 퍼널은 "만료 후 30일 안에 재결제했는가"이며 모집단도 달라 직접 비교하지 않습니다.
- **구독 vs 활동**(paid): 1개월차에는 활동 유지(85.92%)가 구독 유지(83.95%)보다 높고, 3개월차부터 활동이 더 낮아져 12개월차는 활동 64.04%, 구독 70.71%입니다. 구독 유지자 중에도 그 달 청취가 없는 사용자가 10~15% 있습니다. trial은 첫 결제 직후 활동 비율이 64.22%로 paid(94.84%)보다 낮은데 원인은 모릅니다.

## AI 활용과 검증

SQL 초안 작성과 분석 방향 논의에 AI(Claude)를 활용했고, 결과는 그대로 쓰지 않고 다음과 같이 검증했습니다.

- **정의 일관성**: 퍼널의 갱신 판정이 이탈 정의(`01`)와 다르게 작성된 것을 실행 전에 발견해 같은 규칙으로 고쳤습니다.
- **SQL 오류**: 사용자 기준 이탈률이 항상 100%로 나오는 오류를 찾았습니다. 판정 불가 사용자를 분모에서 빼면 남는 사용자가 모두 이탈로 잡혔기 때문이며, 판정 불가를 활동 중으로 취급하도록 고쳤습니다.
- **외부 기준과 대조**: 직접 만든 이탈 정의를 공식 라벨과 비교해 불일치 원인(조기 갱신 185명 등)을 규명했고, 퍼널의 첫 갱신 이탈을 플랜별·결제금액별로 쪼개 무료 체험 집중을 확인했습니다.
- **추정이 아닌 쿼리로 확인**: `user_master`와 퍼널의 99명 차이를 취소 거래만 있는 사용자로 확인했고, AI가 가정한 `has_early_window`의 의미는 SQL을 직접 읽어 바로잡았습니다.
- **재실행 시 값이 흔들리는 문제**: 코호트 세그먼트 인원이 실행마다 2명씩 달라지는 것을 첫 거래 정렬의 동점 처리 문제로 가설을 세워 확인했습니다. 같은 날 같은 만료일에 0원 행과 99원 행이 함께 있는 사용자가 42명(세그먼트가 갈릴 수 있는 사용자 41명)이었고, 결제금액이 큰 거래를 첫 거래로 고정한 뒤 22명이 free_start에서 paid로 옮겨 갔습니다.
- AI가 제시한 가정(취소 거래 제외, 공식 라벨 규칙 등)은 확정 사실이 아니라 데이터로 확인한 추정으로 표시했습니다.

## 한계

- 모든 수치는 1% 샘플 기준이며, 다른 시드나 비율로 안정성을 확인하지 않았습니다.
- 공식 라벨 규칙은 추정이며 약 0.6%는 설명하지 못했습니다. 취소 거래는 시점 구분 없이 갱신에서 일괄 제외했습니다.
- 비취소 거래 중 만료일이 관측 기간 밖이거나 결제일보다 앞서는 거래가 최대 약 149행(0.08%), 영향 사용자는 최대 40명(약 0.2%)입니다. 먼 미래의 만료일은 이탈이 아닌 판정 불가로, 1970년 만료일은 이탈 후 복귀로 잘못 분류될 수 있어 정의는 바꾸지 않고 기록만 했습니다. 코호트의 첫 결제 시점 유지율이 100%가 아닌 것(trial 99.82%, free_start 99.33%, paid 99.98%)도 이 때문으로 추정하지만 확인하지 않았습니다.
- 나이는 50.5%가 결측이며, 원본의 미입력(0)과 범위 밖 이상치가 구분되지 않은 채 결측으로 처리되어 있습니다.
- 무료 체험 여부는 결제금액 0원이라는 근거로 추정했고, free_start의 시작 사유(쿠폰·프로모션 등)는 데이터에 없어 추정입니다. 코호트 유지율의 구독 체크포인트와 활동 창은 같은 시점이 아니며, 활동은 로그 하루 이상이라는 단순 기준입니다. 청취 로그가 전혀 없는 사용자는 free_start 0.94%, paid 0.77%, trial 4.35%입니다.
- 0원 시작자의 갱신 행동 진단은 저장소에 포함하지 않은 일회성 쿼리이며 정렬 고정 전의 값이라, 재계산 후 반영합니다.
- 관찰 데이터이므로 자동 갱신과 갱신률, 구독 유지와 활동 유지의 관계는 상관관계이며 인과가 아닙니다. A/B 테스트는 설계안입니다.

## 실행 방법

1. Kaggle에서 위 데이터를 내려받아 `data/raw/`에 넣고, `pip install -r requirements.txt`로 패키지를 설치합니다.
2. 프로젝트 루트에서 SQL을 순서대로 실행합니다. (DuckDB, 결과는 `data/kkbox.duckdb`에 저장)

```
   python python/run_sql.py sql/00_load_and_sample.sql
   python python/run_sql.py sql/01_churn_definition.sql
   python python/run_sql.py sql/01b_churn_label_diagnosis.sql
   python python/run_sql.py sql/01c_churn_variant_test.sql
   python python/run_sql.py sql/02_build_user_master.sql
   python python/run_sql.py sql/03_funnel.sql
   python python/run_sql.py sql/03b_funnel_by_plan.sql
   python python/run_sql.py sql/03c_trial_check.sql
   python python/run_sql.py sql/04_cohort_retention.sql
```

   `00`은 대용량 로그를 읽어 오래 걸립니다. 샘플링 비율은 `sample_pct`로 바꿀 수 있고, 바꾸면 이 문서의 수치도 달라집니다. `04`는 `01`과 `03` 실행 후에 실행하며 테이블을 `CREATE OR REPLACE`로 만들어 다시 실행해도 같은 결과가 나옵니다.

3. 노트북은 `notebooks/` 폴더에서 위에서 아래로 실행합니다. (Jupyter 필요, DB 경로 `../data/kkbox.duckdb`) `02_cohort.ipynb`는 `04` 실행 후에 실행합니다.

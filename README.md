# 구독 서비스 고객 이탈·리텐션 분석 (KKBox)

> 🚧 **작업 중입니다.** 아래 "진행 현황"에서 완료된 항목만 결과로 인정해 주세요. 모든 수치는 **사용자 1% 샘플** 기준이며 전체 모집단의 값이 아닙니다.

음악 스트리밍 구독 서비스 KKBox의 가입·결제·청취 로그로 **가입 후 고객이 언제, 어떤 특징을 가지고 이탈하는지** 분석하고, 리텐션 개선을 위한 CRM 액션과 A/B 테스트 설계안을 제안하는 포트폴리오입니다.

## 분석 질문

1. 가입한 고객은 첫 결제와 갱신 단계에서 어디서 가장 많이 빠져나가는가? (구독 전환·갱신 퍼널)
2. 가입 후 이탈하는 고객은 어떤 특징을 가지는가?
3. 가입월 코호트별 월별 재방문(유지)율은 어떻게 다른가?
4. 고객 세그먼트별 행동과 유지율, LTV(근사치)는 어떻게 다른가?

### 초기 가설 (분석 후 수정 예정)

- H1. 가입 후 초기 30일 활동이 적은 사용자일수록 이탈 확률이 높다.
- H2. 자동 갱신을 켠 사용자는 이탈률이 낮다.
- H3. 결제수단과 플랜 기간에 따라 유지율이 다르다.

퍼널 분석에서 H2와 H3의 예비 근거를 확인했습니다. 30일 플랜 안에서 자동 갱신 사용자의 1차 갱신률(86.03%)이 수동 갱신 사용자(70.08%)보다 높고, 플랜 종류에 따라 갱신률이 크게 달랐습니다. 다만 다른 변수를 통제하지 않은 단순 비교이므로, 이후 통계 검정과 회귀에서 다시 확인합니다.

## 분석 기준

### 분석 대상(모집단)
- 샘플 회원 중 **결제 이력이 있는 사용자**만 분석합니다 (샘플의 약 30%). 결제 이력이 없으면 갱신·이탈을 정의할 수 없기 때문입니다.
- 가입 초기 행동 지표(청취 로그 기반)를 쓰는 분석은 해당 지표를 쓸 수 있는 9,104명으로 한정합니다.
- 퍼널 분석은 취소 거래를 제외하고 결제 이력을 세므로 `user_master`(19,937명)보다 99명 적은 19,838명이 나옵니다. 취소 거래만 있는 사용자 때문으로 추정하며, 아직 쿼리로 확인하지 않았습니다.

### 이탈 정의
- 기본 정의: **구독 만료 후 N일 안에 재결제가 없으면 이탈**, 기본값은 N=30
- 만료 전에 다음 결제가 이미 있는 조기 갱신과 장기 플랜 연장은 **유지**로 봅니다.
- 취소 거래(`is_cancel=1`)는 갱신으로 인정하지 않고 제외합니다. 이는 가정이며, 취소 시점(만료 전/후)에 따른 구분은 하지 않았습니다.
- 다음 결제가 없고 아직 N일이 지나지 않아 판정할 수 없는 건(censored)은 만료 건 기준 이탈률에서 제외하고, 사용자 기준 이탈률에서는 활동 중으로 취급합니다.

### 민감도 점검 (N = 15 / 30 / 45일)

| 기준 | N=15 | N=30 | N=45 |
|---|---|---|---|
| 만료 건 기준 이탈률 | 9.06% | 7.82% | 7.06% |
| 사용자 최종 이탈률 | 44.9% | 43.8% | 42.8% |

N을 바꿔도 이탈률 수준이 크게 달라지지 않아, 결론이 특정 N 선택에 좌우되지 않는다고 판단했습니다.

### 공식 라벨(`train.csv`)과의 비교
공식 라벨은 2017-02 만료 건 기준이며, 샘플 내 비교 대상은 8,767명(공식 이탈률 6.38%, 559명)입니다.

| 정의 | 일치도 | 공식 이탈자 포착 |
|---|---|---|
| 본 분석의 정의 | 97.51% | 342명 |
| v1: 만료일 이후 결제만 갱신으로 인정, 취소 거래 제외 | 99.43% | 510명 (오분류 1명) |
| v2: v1에서 취소 거래 포함 | 98.84% | - |

- 본 분석의 정의가 놓친 공식 이탈자 217명 중 185명은 만료일 **이전**에 다음 결제가 있는 경우(조기 갱신, 장기 플랜), 27명은 만료 당일, 5명은 만료 후 1~30일 결제입니다.
- 공식 라벨은 "만료일 이후 결제만 갱신으로 본다"는 규칙에 가까운 것으로 보입니다. 다만 이는 **데이터로 추정한 것이며 공식 문서로 확인한 규칙이 아닙니다.**
- v1으로도 설명되지 않는 약 50명(약 0.6%)의 원인은 확인하지 못했습니다.

### 정의 선택
- 분석 기본값은 본 분석의 정의입니다. 조기 갱신도 서비스를 계속 이용하는 것이라 유지로 보는 편이 비즈니스 해석에 맞다고 판단했습니다.
- 공식 라벨 규칙(v1)은 결과의 견고성을 확인하는 민감도·검증용으로 병행합니다.

## 핵심 결과

### 구독 퍼널 (1% 샘플)

| 단계 | A. 전체 샘플 회원 | B. 관측 기간 내 가입 회원 |
|---|---|---|
| 샘플 회원 | 68,018 | 43,619 |
| 관측 기간 내 첫 결제 | 19,838 (29.17%) | 9,097 (20.86%) |
| 가입 후 30일 내 첫 결제 | - | 6,157 / 42,112 (14.62%) |
| 1차 갱신 (판정 가능자 대비) | 12,581 / 19,241 (65.39%) | 5,232 / 8,670 (60.35%) |
| 2차 갱신 (1차 갱신자 중 판정 가능자 대비) | 10,811 / 11,765 (91.89%) | 4,387 / 4,845 (90.55%) |

- A 코호트에는 관측 기간 이전에 가입한 사용자가 섞여 있어 "첫 결제"가 실제 첫 결제가 아닐 수 있습니다. 가입 시점을 알 수 있는 **B 코호트를 기준으로 해석**합니다.
- 1차·2차 갱신 분모는 판정 가능한 건(갱신 또는 이탈로 확정된 건)만 포함합니다.
- 2차 갱신률이 높은 것은 이미 한 번 갱신한 집단이라는 선별 효과가 섞여 있어, 충성도가 높아진다는 근거로 쓰지 않습니다.

### 첫 갱신 이탈은 무료 체험 사용자에 집중되어 있음

B 코호트의 1차 갱신률을 첫 결제 플랜별로 나눈 결과입니다 (판정 가능자 100명 이상인 조합만).

| 첫 결제 플랜 | 자동 갱신 | 판정 인원 | 1차 갱신률 |
|---|---|---|---|
| 30일 | O | 3,972 | 86.03% |
| 7일 | X | 2,236 | **4.87%** |
| 30일 | X | 1,648 | 70.08% |
| 195일 | X | 137 | 63.50% |
| 410일 | X | 134 | 59.70% |
| 31일 | O | 128 | 92.97% |

- 7일 플랜 첫 결제의 대부분(2,237명 중 2,226명)은 정가와 결제 금액이 모두 0원입니다. **무료 체험으로 추정**하며, 이 집단의 유료 전환(1차 갱신)률은 4.76%(2,226명 중 106명)입니다.
- 7일 플랜 사용자는 판정 가능자의 약 26%이지만 첫 갱신 이탈 3,438건 중 약 62%가 여기서 나옵니다.
- 체험으로 시작하지 않은 사용자의 첫 갱신률은 79.62%(6,434명 중 5,123명)입니다. "첫 갱신에서 약 40%가 이탈한다"는 숫자는 **체험 → 유료 전환**(약 95% 미전환)과 **유료 갱신**(약 20% 이탈)이 섞인 값이므로 둘을 나누어 다룹니다.
- 30일 플랜 안에서 자동 갱신 사용자(86.03%)가 수동 갱신 사용자(70.08%)보다 갱신률이 높습니다. 관찰 데이터이므로 자동 갱신의 효과로 단정하지 않습니다.
- 전체 만료 건 기준 이탈률(7.82%)이 낮은 것은 2차 이후 갱신이 건수 대부분을 차지하기 때문입니다.

## AI 활용과 검증

이 프로젝트는 SQL 초안 작성과 분석 방향 논의에 AI(Claude)를 활용했습니다. AI가 만든 결과를 그대로 쓰지 않고 다음과 같이 검증했습니다.

- **지표 정의의 일관성 확인**: 퍼널의 갱신 판정이 이탈 정의(`01`)와 다르게 작성된 것을 실행 전에 발견해 같은 규칙으로 고쳤습니다. 수정 전 판정은 다음 결제가 있는 건까지 판정 불가로 빼서 갱신률이 왜곡될 수 있었습니다.
- **SQL 오류 수정**: 사용자 기준 이탈률이 항상 100%로 나오는 오류를 발견했습니다. 판정 불가 사용자를 분모에서 빼면 남는 사용자가 모두 이탈로 잡히기 때문이었고, 판정 불가를 활동 중으로 취급하도록 고쳤습니다.
- **공식 라벨로 정의 검증**: 직접 만든 이탈 정의를 공식 라벨과 비교하고 불일치 원인(조기 갱신 185명 등)을 규명했습니다.
- **결과 해석 점검**: 퍼널에서 눈에 띈 첫 갱신 이탈을 플랜별로 쪼개 보고, 결제 금액까지 확인해 무료 체험 집단에 집중되어 있음을 확인했습니다.
- AI가 제시한 가정(취소 거래 제외, 공식 라벨 규칙 등)은 확정 사실이 아니라 데이터로 확인한 추정으로 표시했습니다.

## 한계

- 모든 수치는 1% 샘플 기준이며 표본 변동이 있습니다. 샘플링 비율을 바꾸거나 다른 시드로 뽑아 안정성을 확인하지 않았습니다.
- 공식 라벨 규칙은 데이터로 추정한 것이며 약 0.6%는 설명하지 못했습니다.
- 취소 거래를 갱신에서 제외한 가정은 취소 시점에 따른 구분 없이 일괄 적용했습니다.
- 무료 체험 여부는 결제 금액 0원이라는 데이터 근거로 추정한 것입니다.
- 관찰 데이터이므로 자동 갱신 등 변수와 갱신률의 관계는 상관관계이며 인과가 아닙니다.
- A/B 테스트는 설계안이며 실제 실험 결과가 아닙니다.

## 실행 방법

1. Kaggle에서 위 데이터를 내려받아 `data/raw/`에 넣습니다.
2. 패키지를 설치합니다.

   ```
   pip install -r requirements.txt
   ```

3. 프로젝트 루트에서 SQL을 순서대로 실행합니다. (DuckDB, `data/kkbox.duckdb`에 결과 저장)

   ```
   python python/run_sql.py sql/00_load_and_sample.sql
   python python/run_sql.py sql/01_churn_definition.sql
   python python/run_sql.py sql/01b_churn_label_diagnosis.sql
   python python/run_sql.py sql/01c_churn_variant_test.sql
   python python/run_sql.py sql/02_build_user_master.sql
   python python/run_sql.py sql/03_funnel.sql
   python python/run_sql.py sql/03b_funnel_by_plan.sql
   python python/run_sql.py sql/03c_trial_check.sql
   ```

   `00`은 대용량 로그를 읽어 시간이 오래 걸립니다. 샘플링 비율은 `00_load_and_sample.sql`의 `sample_pct`로 바꿀 수 있으며, 바꾸면 이 문서의 수치도 달라집니다.
